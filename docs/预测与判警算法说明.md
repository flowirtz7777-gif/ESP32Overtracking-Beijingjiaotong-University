## 0. 一句话总览

每 20 ms 用一组实时传感器值 `(v, α, φ)` 推算未来 0.3 / 1.0 / 2.0 秒挂车右侧外缘扫过的地面区域，构成三层嵌套危险多边形 `PolyI ⊂ PolyA ⊂ PolyW`，再判断雷达目标是否落入这些多边形里，输出 4 级风险等级。

---

## 1. 输入与符号约定

### 1.1 实时输入（每 20 ms 一组）

| 符号 | 含义 | 单位 | 来源 |
|---|---|---|---|
| v | 牵引车前轮速度 | m/s | OBD CAN |
| α | 前轮转向角 | rad | AS5600 |
| φ | 铰接角（牵引车 - 挂车航向差） | rad | 角度电位计 |
| `(rᵢ, βᵢ, vᵢ)` | 雷达目标 i 的距离、角度、径向速度 | m, rad, m/s | LD2450 |

### 1.2 车辆固定参数

| 符号 | 含义 | 默认值 | 单位 |
|---|---|---|---|
| l | 牵引车轴距 (前轮 A → 后轴中心 B) | 4.0 | m |
| l_h | 后悬长度 (B → 鞍座 H) | 1.8 | m |
| L | 挂车轴距 (H → 挂车后轴中心 T) | 13.5 | m |
| W | 等效车宽 | 2.0 | m |
| φ_max | 铰接角硬限幅 | 15° (CSV 字段 `phi_max_rad`) | deg/rad |

### 1.3 车体坐标系

原点取**牵引车后轴中心 B**，x 轴指向车头，y 轴指向左侧。所有外部传感器数据先做坐标变换到此系再参与判内。

### 1.4 派生几何点

```
A = B + l   · (cos θ, sin θ)         ← 牵引车前轮中心
H = B + l_h · (cos θ, sin θ)         ← 鞍座牵引销 (挂车前端)
θ_t = θ - φ                          ← 挂车航向
T = H - L · (cos θ_t, sin θ_t)      ← 挂车后轴中心 (挂车后端)
```

挂车车身 = H 到 T 的直棍 (长度 L)，挂车右侧外缘是这根直棍向右法向偏移 W/2:
```
H_right = H + (W/2) · ( sin θ_t, -cos θ_t)
T_right = T + (W/2) · ( sin θ_t, -cos θ_t)
```

## 2. 运动学 (kinematics_step.m)

状态向量 `s = [xB, yB, θ, φ]`，欧拉一步推进：

```
omega1 = v · sin(α) / l                                   // 牵引车横摆率
vB     = v · cos(α)                                       // 牵引车后轴中心纵向速度

omega2 = ( vB · sin(φ) + l_h · omega1 · cos(φ) ) / L     // 挂车横摆率
vT     =   vB · cos(φ) - l_h · omega1 · sin(φ)           // 挂车纵向速度 (备用)

xB ← xB + vB · cos(θ) · dt
yB ← yB + vB · sin(θ) · dt
θ  ← θ  + omega1 · dt
φ  ← φ  + (omega1 - omega2) · dt
φ  ← clamp(φ, -φ_max, +φ_max)
```

**关键性质**：直行时 `α=0, omega1=0`，所以 `dφ/dt = -vB·sin(φ)/L`，**φ 自然衰减回 0** (时间常数 τ = L/vB ≈ 4.5s @ vB=3 m/s)。这反映了实车物理：挂车直行时铰接角自动收敛。

**MATLAB 与 HTML 对齐**：`kinematics_step.m` 与 `pid工况仿真导出器.html` 使用完全相同的方程，验证时 (xB, yB, θ, φ) 误差在 mm / arcsec 量级。

## 3. 扫掠多边形构造 (predict_swept.m)

### 3.1 核心思想

给定当前状态 `s0` 和 `(α, v)`，假设短时内 α 保持不变 (顶层文档"短时合理假设"之一)，从 `s0` 用 `kinematics_step` 向前推 `T_h` 秒。每一步记录挂车右侧外缘的两个端点 `H_right(t), T_right(t)`，最终形成扫掠多边形。

### 3.2 多边形原始构造

四类边：

```
              H_right_0 ━━━━ (H_right 弧线) ━━━━ H_right_E
                  │                                  │
                  │                                  │
        起始车身右沿 ┃                          ┃ 结束车身右沿
        (直，t=0)   ┃                          ┃ (直，t=T_h)
                  │                                  │
              T_right_0 ━━━━ (T_right 弧线) ━━━━ T_right_E
```

顶点序列：
```
H_right_0 → H_right_1 → ... → H_right_M
        → T_right_M → T_right_{M-1} → ... → T_right_0
        → 闭合回 H_right_0
```

### 3.3 自相交问题（蝴蝶结）

挂车后轴没有转向能力，转弯时挂车尾部 (T 点) **远离弯心方向甩出**。这导致：

- H_right 弧线偏向**弯心内侧**（车头朝弯心内推进）
- T_right 弧线偏向**弯心外侧**（车尾外甩）

两条弧线在世界坐标系里**交叉**，形成"蝴蝶结/漏斗"形自相交多边形：

```
    ╱╲
   ╱   ╲     ← 弯心一侧扫过的真实危险区
  ╱  ✓  ╲
  ╲     ╱
   ╲   ╱
    ╳        ← 自相交点
   ╱   ╲
  ╱  ✗  ╲    ← "外甩三角"，是车走过的空地，不构成危险
   ╲   ╱
    ╲╱
```

### 3.4 B2 解决方案：polyshape 偶奇规则简化

```matlab
ps = polyshape(boundary_x, boundary_y, 'Simplify', true);
% 取面积最大的区域作为有效危险区
if ps.NumRegions > 1
    [~, idx_max] = max(arrayfun(@area, regions(ps)));
    poly = regions(ps)(idx_max).Vertices;
end
```

`polyshape Simplify` 用偶奇填充规则在交叉处把多边形拆分。"外甩三角"通常是较小的独立区域，被丢弃。**保留弯心侧的真实危险区**。

### 3.5 三层时间窗

| 多边形 | T_h | 在 v=3 m/s 时纵向覆盖 | 报警等级 |
|---|---|---|---|
| `PolyW` | 2.0 s | ~6 m | 1 = 黄色警告 |
| `PolyA` | 1.0 s | ~3 m | 2 = 红色报警 |
| `PolyI` | 0.3 s | ~0.9 m | 3 = 立即危险 |

每层独立调用 `predict_swept`，得到三个嵌套多边形（`PolyW ⊃ PolyA ⊃ PolyI`，因为 T_h 越短面积越小）。

### 3.6 内部积分步长

```
dt_pred = 0.01 s   (每个 T_h 切成 N 段)
PolyW: 200 步
PolyA: 100 步
PolyI:  30 步
```

ESP32 浮点跑这个步长 < 0.5 ms，不构成实时性瓶颈。

### 3.7 α 外推假设（当前禁用）

`predict_swept` 接受可选参数 `alpha_dot` 让 α 在 T_h 内线性外推：`α(τ) = α₀ + α_dot · τ`。

但实测发现：PID 输出 α 含高频抖动，相邻两点差分估出的 α_dot 噪声大，2 秒外推被放大成多边形发散。**当前 demo 默认 α_dot = 0**（α 短时保持当前值）。

未来如需启用：α_dot 必须先经低通滤波，且函数内部已做 ±π rad/s 限幅作为双保险。

## 4. 风险评估 (run_phase1_demo.m, risk_eval 待独立)

### 4.1 单目标风险等级

对每个雷达目标 i，对当前帧的三层多边形分别判内。同时必须额外判定一次**当前挂车矩形占用区**：

```matlab
in_W = inpolygon(target_x, target_y, PolyW)
in_A = inpolygon(target_x, target_y, PolyA)
in_I = inpolygon(target_x, target_y, PolyI)

in_body_now = inpolygon(target_x, target_y, BodyNow)
if in_body_now
    in_I = true
    in_A = true
    in_W = true
end

Risk_i = 0           if 全 false
       = 1 (黄)      if in_W only
       = 2 (橙)      if in_A
       = 3 (红)      if in_I
```

> 嵌套关系保证：`in_I ⇒ in_A ⇒ in_W`（点在最严的区里必然也在外两层）。

**2026-05-30 修正说明（给 Claude / 后续维护者）**：

`PolyW/A/I` 描述的是从当前时刻开始、未来一段时间内“右外缘线”扫过的区域。它不能替代当前车身矩形占用区判定。一个目标可能已经被右外缘扫过、此刻落在挂车车身投影内部；这时如果只看“未来右外缘扫掠”，会误判为安全。

实测例子：`pid_scenario_20260530_020804.csv` 中 R3 位于 `(15.162112188, 34.264469347)`，真实挂车车身在 `t≈16.24–18.12 s` 覆盖该点。旧版 `run_phase1_demo.m` 只判未来扫掠多边形，因此给 R3 输出风险 0；修正后在每个关键帧加入 `BodyNow` 兜底，R3 输出风险 3。

当前 `BodyNow` 构造：

```matlab
d = derive_points(s, p)
right_normal = [sin(d.theta_t), -cos(d.theta_t)]
BodyNow = [
    H + W/2 * right_normal
    T + W/2 * right_normal
    T - W/2 * right_normal
    H - W/2 * right_normal
]
```

移植到 ESP32 / `risk_eval` 时也必须保留这个兜底：**当前车身占用区命中 = 立即危险（Risk 3）**。

### 4.2 R3 报警偏晚复盘结论（2026-05-30）

`pid_scenario_20260530_020804.csv` 中 R3 是一个重要反例：

```text
R3 = (15.162112188, 34.264469347)
真实挂车车身覆盖时间 ≈ 16.24 s - 18.12 s
```

用完整 CSV 真值轨迹复盘可得：

```text
t = 14.24 s: true TTC ≈ 2.00 s
t = 15.24 s: true TTC ≈ 1.00 s
t = 16.00 s: true TTC ≈ 0.24 s
```

但当前在线预测口径默认 `alpha(τ)=alpha_now`，在弯道后段 / 转向角快速回正阶段会低估后续挂车右侧车身外缘（尤其前中段）的扫掠趋势。R3 的现象是：按后验真值看应在 2 s 左右进入黄色预警，但恒定 `alpha_now` 的短时 poly 预测发现偏晚，接近碰撞时才升到高等级。

注意：这里不应笼统写成“挂车尾部扫到人”。半挂车转弯时后轴/尾部常会相对弯心外甩，远离内轮差危险区；真正容易形成内侧挤压的是牵引销 H 到挂车中部一带的右侧车身外缘向弯心内侧切入。尾部是否会扫到目标取决于目标相对车身的位置和外甩方向，不能一概而论。

这不是 Python 复盘程序的错误，也不意味着在线端可以直接使用 true TTC。结论是：

- **在线主算法仍使用当前 `(v, alpha, phi)` → `predict_swept` → `PolyW/A/I` 判定**。
- **true TTC 只用于复盘评估主算法提前量**。
- R3 暴露出当前 `alpha_dot=0` 假设在部分工况下可能预警偏晚，需要后续改进。

建议改进方向：

1. 对 `alpha_dot` 做低通滤波后启用短时线性外推：`alpha(τ)=alpha_now + alpha_dot_filtered·τ`。
2. 同时保留 `alpha_dot=0` 分支，与外推分支取并集，避免外推噪声导致漏判或误判。
3. 引入目标安全膨胀半径 / 目标宽度；当前只判目标中心点，R3 这类贴边目标对提前量很敏感。
4. 用 `truck_slider_sim.py` / `TTC预警复盘软件` 批量输出 true TTC 与 poly 首次报警时间差，作为参数调优指标。

### 4.3 全局风险

```
Risk_total = max_i Risk_i
```

任一目标进入立即危险区即触发 3 级报警。

### 4.4 待办：TTC + 状态机滞回

完整版风险评估还应包括：

- **TTC (Time-To-Conflict)**：用目标速度 `(vx, vy)` 外推未来轨迹，找最早进入 PolyA 的时间 τ
- **状态机滞回防抖**：连续 N_up = 2 帧 (40 ms) 满足升级条件才升级；连续 N_down = 10 帧 (200 ms) 失败才降级

这些在 CLAUDE.md / AGENTS.md 第 4.3、4.4 节有详细规范，等 Phase 2 实装。

## 5. 完整数据流（每 20 ms 一周期）

```
┌────────────────── 20 ms 主循环 ──────────────────┐
│                                                    │
│  ① 读传感器                                        │
│     v   ← CAN                                      │
│     α   ← AS5600                                   │
│     φ   ← 角度电位计                               │
│     雷达目标 [(xᵢ, yᵢ, vxᵢ, vyᵢ)]                  │
│                                                    │
│  ② 状态构造                                        │
│     s = [xB=0, yB=0, θ=0, φ_measured]              │
│     (车体系自参考，每周期重置)                      │
│                                                    │
│  ③ 三层扫掠多边形预测                              │
│     PolyW ← predict_swept(s, α, v, 2.0, 0.01)      │
│     PolyA ← predict_swept(s, α, v, 1.0, 0.01)      │
│     PolyI ← predict_swept(s, α, v, 0.3, 0.01)      │
│     每层内部用 polyshape 剔除外甩三角              │
│                                                    │
│  ④ 目标判内                                        │
│     BodyNow ← 当前挂车矩形占用区                    │
│     for each radar target i:                       │
│         if p_i ∈ BodyNow: Risk_i = 3               │
│         else Risk_i = max level (W/A/I) it falls in│
│                                                    │
│  ⑤ 全局风险 + 状态机                              │
│     Risk = max_i Risk_i                            │
│     FSM(Risk) with hysteresis → S ∈ {0,1,2,3}      │
│                                                    │
│  ⑥ 报警输出                                        │
│     S=0  off                                       │
│     S=1  yellow LED solid                          │
│     S=2  red LED solid + buzzer 250 ms beep        │
│     S=3  red LED solid + buzzer continuous         │
│                                                    │
└────────────────────────────────────────────────────┘
```

## 7. 局限与未来工作

### 7.1 当前局限

1. **只考虑右侧扫掠**：右侧版本已实现，左侧 (`predict_swept_left`) 在 TODO.md 第 2 项
2. **只考虑挂车车身**：牵引车头扫掠忽略 (用户决定)。实车若车头悬出明显，需加 `front_overhang_m` 字段
3. **静态预测**：每周期重新预测，没有跨周期跟踪。未来可加 **目标 CV 外推 + Kalman 关联**
4. **PID 工况验证**：当前 demo 输入是 PID 仿真器生成的"虚拟驾驶员"工况，不是真车数据。Phase 4 实车回放时再换真数据
5. **α 外推关闭**：α(τ) ≡ α₀ 短时假设简单稳定，但 R3 复盘显示在弯道后段 / 转向角快速回正阶段可能导致报警偏晚。实车若 ADC 噪声可控，应启用低通后的 `alpha_dot` 线性外推，并与 `alpha_dot=0` 分支取并集。

### 7.2 Phase 2/3/4 规划

- **Phase 2**：硬件接口（CAN 解码 / LD2450 帧解析 / α/φ 标定）→ ESP32 端 `predictor.{h,cpp}`
- **Phase 3**：OpenMV 视觉协处理 → 雷达-视觉融合
- **Phase 4**：实车低速测试 → 申报书 / 论文 / 专利

详见 `CLAUDE.md` / `AGENTS.md` 路线图章节。

### 7.3 可改进方向（设计取舍点）

| 点 | 当前选择 | 替代方案 | 触发条件 |
|---|---|---|---|
| 积分方案 | Euler @ dt_pred=0.01s | RK4 @ dt_pred=0.05s | 位置误差需要 < 0.1 mm |
| 多边形构造 | polyshape simplify 取最大区域 | 凸包 / 弦版四边形 | 性能瓶颈或几何反直觉 |
| α 外推 | 关闭 (α 保持) | LPF 后线性外推 + 与 α 保持分支取并集 | R3 类工况 true TTC 显示 poly 报警偏晚 |
| 目标尺寸 | 只判中心点 | 目标半径/宽度膨胀或 poly 膨胀 | 目标贴近车身边界，提前量不足 |
| φ 限幅 | 跟 CSV phi_max_rad 字段 | 硬编码 45° | 实车铰接器有不同硬限位 |
| 报警状态机 | 即时切换 | 滞回 (2 帧/10 帧) | 边界目标频繁进出造成抖动 |
