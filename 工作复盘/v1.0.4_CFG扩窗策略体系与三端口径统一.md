## 三、关键技术成就（论文/答辩可用）

1. **segment_swept 逐段扫掠判定**：把整段预测窗拆成相邻预测步右边缘的小扫掠
   四边形逐段判内，避免长窗口大 Poly 自交/退化造成"3s 扩窗反而漏掉 2s 已覆盖
   点"。从原理上保证**扩窗单调性**——扩窗后首报不晚于默认策略。这是把"扩窗"
   从直觉变成可证明性质的关键一步。

2. **CFG 策略 + 三端口径统一**：用一份 CFG JSON 驱动状态机判相位、分相位选窗口、
   segment_swept 统计命中。网页/MATLAB 校验/阈值扫描三端读同一 CFG，
   `docs/CFG扩窗算法一致性说明.md` 固化权威口径，杜绝"各程序各判一套"。

3. **仅 EXIT 扩窗时序验证**：EXIT 在 15.48s 触发、早于 R3 报警 15.80s，证明
   阶段化扩窗在危险点报警前生效，不是空摆设。

4. **配置与判定分离**：CFG 生成器只产配置不参与判定，主分析软件才是裁判——
   职责清晰，便于后续批量扫描不同 CFG。

## 四、风险与注意点

### 风险 1：CFG 扩窗的净收益尚未系统量化

工具链已就绪（扫描器接了 CFG），但还没跑出"固定窗 vs CFG扩窗"的全图盲区
数量对比表。在拿这个做论文结论前必须补这一步，避免重蹈"只看 R3 一个点"的覆辙。

### 风险 2：90° 正交路口假设（沿用 v1.0.3）

`exit_heading_delta_deg_min=75°` 默认值假设标准十字右转。真车非 90° 路口
EXIT 可能不触发。CFG 已可调该阈值，但需要真车数据标定。

### 风险 3：exit_hold_frames 默认从 3 降到 2

状态机 EXIT 去抖帧数默认值本版从 3 改为 2，相位判定更敏感。PID 平滑工况无碍，
真车脏信号下需复核是否够稳。

### 风险 4（沿用）

HTML 轴距硬修正 ~4mm 残差；实车 α/φ 标定占位；硬件团队进度。

## 七、本版核心教训

1. **把硬编码变成可配置是正确的工程化方向**：v1.0.3 的"仅 EXIT 扩窗"是写死的
   常量，本版抽成 CFG 后，调参/对比/复现都变得可控，且强制三端口径统一。

2. **扩窗必须先保证单调性再谈收益**：segment_swept 解决的不是"扩窗效果好不好"，
   而是"扩窗会不会因为几何退化反而变差"这个更底层的正确性问题。先把性质证对，
   再谈调参收益。

3. **BAT 中文路径的坑会复发**：PID 导出器这次又栽在 GBK 乱码上（和 TTC 复盘
   软件当初同一个坑）。DO-NOTs 第 8 条早写了，但新建工具时容易忘。教训：
   所有带中文路径的 BAT 一律单行调 PowerShell 启动器，别再写多行 cmd。
