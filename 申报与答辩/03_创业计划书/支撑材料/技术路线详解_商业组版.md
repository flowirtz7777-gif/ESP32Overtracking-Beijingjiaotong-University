## 0. 一句话看懂整个技术路线

**系统用“感知 → 预测 → 危险区 → 判警 → 报警”五步闭环，回答一个核心问题：半挂车右转时，未来 0.3/1.0/2.0 秒内右侧车身会扫过哪些地方，有没有人/电动车在里面。**

技术路线 = “算法先仿真验证，再移植到低成本硬件”：

```text
PID/人工驾驶工况（虚拟传感器数据）
        ↓
MATLAB + 网页仿真验证（运动学重算、误差<1mm 门控）
        ↓
算法移植到 ESP32-S3 嵌入式平台（20ms 实时循环）
        ↓
毫米波雷达 + 视觉 + （规划中：北斗高精度定位）多源感知
        ↓
分级声光报警 + 数据记录
```

【商业组注释】你们 PPT 里“解决方案”一页的五步（传感器采集 → 几何模型预测 → 雷达目标探测 → 空间匹配算法 → 分级声光报警）就是上面这条链的产品化表达；本文是它的技术底稿。

## 1. 问题定义与设计哲学

### 1.1 这不是“控制问题”，而是“短时风险预测问题”

- 系统**不替司机开车**，不生成理想转弯轨迹，不做长期驾驶意图识别；
- 系统只回答：**按当前车速、方向盘角度、铰接角继续开，未来几秒右侧车身会扫过哪里，目标是否会被扫到**。

【人话】它像一个“提前 2 秒的电子眼”：不等撞上才报警，而是预测车身未来会压过的区域。

### 1.2 内轮差风险 = 未来短时“扫掠危险区”，不是单个距离值

- 传统做法把内轮差描述成一个“距离数”，只能做几何分析，不能直接预警；
- 本项目把风险表达为**右侧车身边界在未来短时域内扫过的地面区域**，再判断目标是否进入，直接服务于“提前多久报警”。

【商业组注释】这是与竞品（固定扇形雷达区、固定阈值报警）最本质的差异点，也是“白盒、可解释”卖点的来源。

### 1.3 主模型 vs 对照模型

| 角色 | 模型 | 用途 |
|---|---|---|
| 主模型 | 实时状态 + 短时耦合运动学预测 + 三层危险区 | 车上最终判警 |
| 对照 1 | PID 轨迹生成 | 生成平滑工况 + 对照组（已重新定位，不再是判警主模型） |
| 对照 2 | 静态扩张危险带 | 证明“无预测”方案提前量不足 |
| 对照 3 | 单体/自行车模型简化 | 证明忽略挂车姿态会漏掉挂车扫掠 |

【人话】主模型是“正牌选手”，PID 等是“陪练”，用来证明正牌选手更优。

## 3. 核心算法逐层拆解

### 3.1 车辆几何抽象（A/B/H/T 四点）

把半挂车抽象成一条“铰接的棍子”：

```text
   A ──── B ──── H ════════ T
 前轴   后轴中心  牵引销     挂车后轴中心
  │<─l──>│<─l_h─>│<────L────>│
```

- A = 前轮中心；B = 牵引车后轴中心（车体系原点）；H = 鞍座/牵引销；T = 挂车后轴中心；
- θ = 牵引车航向；θ_t = 挂车航向；φ = θ − θ_t = 铰接角；
- 车体系约定：原点 B，x 向前，y 向左（所有外部传感器先转到这个系再判警）。

【人话】记住四个字母：A 车头、B 后轴、H 铰接点、T 挂车尾。预测危险区就是预测 H–T 这根“棍子”的右边缘未来扫过哪里。

### 3.2 耦合运动学模型（算法心脏）

状态 `s = [xB, yB, θ, φ]`，每个 20ms 周期递推：

```text
ω1 = v·sin(α) / l                          # 牵引车横摆率（转弯快慢）
vB = v·cos(α)                              # 后轴纵向速度
ω2 = (vB·sin(φ) + l_h·ω1·cos(φ)) / L      # 挂车横摆率（关键：含 l_h 耦合项）
xB += vB·cos(θ)·dt
yB += vB·sin(θ)·dt
θ  += ω1·dt
φ  += (ω1 − ω2)·dt，并限幅 |φ| ≤ φ_max
```

**为什么 l_h 耦合项不能丢**：牵引车转弯时，牵引销（H 点）不只是随 B 平移，还会因后悬长度 l_h 产生额外线速度，从而影响挂车转向快慢。省略它，挂车轨迹就推错了——这正是“单体简化模型”会漏报挂车扫掠区的原因。

**自回正性质**：直线行驶时 φ 会自动收敛回 0（时间常数约 4.5s @ 3m/s），符合实车物理。

【状态】MATLAB 端已实现并验证（`kinematics_step.m`），与网页端同方程；误差毫米/角秒量级。

### 3.3 三层扫掠危险区（PolyI / PolyA / PolyW）

| 区域 | 预测时间窗 | 通俗含义 | 报警等级 |
|---|---|---|---|
| PolyW | 2.0 s | 黄色预警区（最远） | 1 黄 |
| PolyA | 1.0 s | 红色报警区 | 2 红 |
| PolyI | 0.3 s | 立即危险区（基本要撞） | 3 紧急 |

构造方法：从当前状态出发，按小步长向前推演，记录每一时刻挂车右边缘两点（H_right、T_right），连成扫掠多边形。

**自相交（蝴蝶结）问题**：挂车尾部会向弯心外侧甩出，形成“外甩三角”，但那不是真危险区。用 `polyshape` 的偶奇规则拆分后**只保留面积最大的弯心侧危险区**。

【人话】三个区域就是“黄、橙、红”三个套在一起的圈，越靠内越紧急；红色扫到基本就要撞了。

### 3.4 目标感知与坐标统一

1. 雷达给出目标在“雷达安装点”的相对坐标；先转到车体系（安装偏移 + 波束偏角标定）；
2. 车体系再转到世界系（用当前位姿 xB/yB/θ）；
3. **BodyNow 兜底**：目标只要已落入当前挂车车身矩形（不是未来区域），直接判 Risk 3——修复过一个真实漏报反例（R3 目标曾被判为安全，实际车身 16.24–18.12s 覆盖它）。
4. 视觉识别目标类别（行人/非机动车/汽车），与雷达目标做关联融合。

【规划中·北斗】北斗 RTK 提供厘米级绝对位置、高精度对地测速、双天线测向，作为车体状态的**独立时空真值**：既校正 xB/yB/θ（此前靠运动学积分，会漂），又让“车体系↔世界系”变换有了绝对基准；预警事件还能结合北斗轨迹沉淀“路口级风险时空数据”。

### 3.5 风险判定与分级报警

```text
对每个目标：
  落在 PolyI 内 → Risk 3（紧急）
  落在 PolyA 内 → Risk 2（报警）
  落在 PolyW 内 → Risk 1（预警）
  否则         → Risk 0
  当前车身占用区命中 → 直接 Risk 3
全局风险 = 所有目标的最大风险
```

报警状态机带**滞回防抖**：

- 升级需连续 2 帧（40ms）满足条件；
- 降级需连续 10 帧（200ms）失败；
- 输出：0 关 / 1 黄灯 / 2 红灯+蜂鸣 250ms 周期 / 3 红灯+连续蜂鸣。

【人话】防止“闪一下就不响”的抖动误报——连续确认才升档，持续一段时间没问题才降档。

### 3.6 出弯状态机（针对“提前量不足”的改进）

转弯过程分五个阶段：

```text
IDLE（未转弯）→ ENTRY（入弯）→ MID（弯中）→ EXIT（出弯）→ DONE（结束）
```

- 入弯判据：|α| ≥ 2° 连续 2 帧（当前无转向灯输入，用转向角阈值模拟）；
- 弯中：累计航向变化 ≥ 25°；
- 出弯：累计航向 ≥ 75° 且 α 回正 / φ 仍有滞后；
- 结束：累计航向 ≥ 88° 且 α、φ 回小，连续 10 帧。

**为什么出弯要“扩窗”**：实测反例 R3 在弯道后段，恒定转向角预测会低估扫掠，导致报警偏晚；出弯阶段把预测窗口从 2/1/0.3s 扩到 3/1.5/0.5s（由 CFG 策略文件控制，可调）。

【商业组注释】“提前量不足/误报警”正是你们市场页对比表里竞品的痛点；状态机+CFG 是我们解决“提前量”的技术答案。

### 4.1 “盲区”的科学定义（商业组要知道的）

盲区点 = 首次黄警时，距离真实接触时间已不足反应时间（默认 1.0s）的点：

```text
lead_W = 真实接触时间 − 首次 PolyW 报警时间
lead_W < 反应阈值  → 盲区点（BLINDSPOT_REACTION_INSUFFICIENT）
```

### 4.2 alpha 五方案对比结论（论文可直接引用）

- 平滑 PID 工况下，外推类方案与基线几乎重合（PID 输出转向角变化本来就平滑）；
- 多假设并集方案面积从 4.56m² 增到 6.88m²，但 R3 提前量无实质改善 → 定位为“保守并集对照”，不作主推；
- 扇形包络是“绝不漏报”的理论上界，但面积过大 → 反衬其他方案合理性。

【商业组注释】这条“我们做过系统性对照实验”的结论，是答辩和材料里体现严谨性的素材。

## 6. 北斗结合方案（新方向）

### 6.1 定位（不过度承诺）

北斗不是替代雷达，而是给系统补“绝对时空基准”：

| 北斗能力 | 精度 | 在项目里的用途 |
|---|---|---|
| RTK 定位 | 厘米级 | xB/yB 直接测量，替代积分（不漂移） |
| 多普勒测速 | 0.03–0.1 m/s | 替代/校正 CAN 车速（不打滑） |
| 双天线测向 | 0.1°–0.5° | 直接测牵引车航向，甚至直接测铰接角 |
| 授时 | ns 级 | 多传感器时间戳统一 |

### 6.2 坐标系对接（关键技术细节）

- 仿真 CSV 的 (0,0) = 车辆起点（本地米制坐标），x 向东、y 向北、θ 从 +x 逆时针；
- 北斗原始输出是经纬度/高程 → 选起点（或路口中心）为原点转成 ENU 米制，即得到 CSV 同款 xB/yB；
- 航向换算：`θ = 90° − 北向航向角`（两个基准不同，必须转换）；
- 雷达目标留在车体系判定，北斗只管“世界系基准”，两者通过位姿变换链衔接。

### 6.3 延伸价值

预警事件 + 北斗轨迹 + 路口几何 → 路口级风险时空数据 → 盲区黑点识别与治理（对应北斗大赛“时空信息治理/交通应用”赛道）。

### 8.2 评审可能问的技术问题（预设答案）

1. **为什么不用激光雷达？** 成本高、难以改装，低速右转场景毫米波+视觉已够，且我们有预测算法弥补探测区域固定问题。
2. **没真车怎么验证？** 仿真驱动：PID/人工驾驶生成数据 → 运动学重算误差<1mm → 盲区分析/TTC 复盘；硬件阶段再做台架与低速实测。
3. **会误报吗？** 分级+滞回（40ms 升级/200ms 降级）+ BodyNow 兜底，兼顾不误报与不漏报。
4. **和竞品差异？** 竞品是“固定区域触发”，我们是“预测未来扫掠区”，提前量可量化（lead_W），且模型白盒可解释。
