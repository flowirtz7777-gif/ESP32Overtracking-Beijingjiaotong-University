# 中期答辩临时训练

> 中期答辩临时训练：基于接触标签纠错前评分，非冻结科研资产。作者标记：Kiro，2026-10-22。分支 `deepseek/midterm-defense-20261022`。规划见 [PLAN.md](PLAN.md)，全部图片及说明见 [全部图表/](全部图表/README.md)。

## 口径

- 只读使用 Z 盘已有评分，不新增仿真，不改冻结资产。
  - S1、S2 用 v3 评分口径，误报类数值比修正口径略高，迟报和漏报不受影响。
  - S3、S4 用修正评分口径。
- 全部轨迹转角峰值都是 10°。结论只适用于这一种转弯几何、2–4 m/s 低速、静态目标、无侧滑的运动学仿真。
- 接触标签纠错尚未完成。三类口径分开看：
  - 端点误差与标签无关。
  - 配对差有 DeepSeek 区间旁证（`描述性图表/fig12`）。
  - 绝对值只作描述。
- 代理模型只是电脑端分析工具，不替代车载预测器，也不作为安全结论。
- **这里的模型不直接转为正式模型。** 正式研究要等纠错完成、数据更新、全部实验完成后，重新冻结数据、分组、评估协议和训练版本，再训练正式模型。正式研究可以复用本目录的 Pipeline、任务组织和绘图代码。

## 运行

```powershell
powershell -ExecutionPolicy Bypass -File run_all.ps1          # P0 → 5 个训练窗口并行 → 汇总
powershell -ExecutionPolicy Bypass -File run_all.ps1 -Only M3  # 只重跑某个模型族
```

- 每一步各开一个可见的 PowerShell 窗口，显示进度条、已用时间、剩余时间和最近一折成绩。日志写入 `logs/`。
- 每次运行前，各步骤先清空自己的 `data/`、`results/`、`model/`、`figures/`，不会混入上一次的结果。
- 汇总步骤在以下任一情况下报失败，不会出"完成"结论：
  - 有模型族未完成、缺结果，或任务数少于定义。
  - 模型加载验证失败、一个模型都没找到，或保存的模型名单与分档不一致。
  - 描述性图表或图表汇集失败。

依赖版本：scikit-learn 1.9.1、numpy 2.4.4、pandas 3.0.2、scipy 1.18.1、matplotlib 3.10.9、Python 3.14.4，随机种子 20261022。

## 评价规则

- **临时模型表现分档**只衡量代理模型对当前（纠错前）评分的预测能力，不代表评分正确、实验完成或安全性通过，和正式科研准入分开。
  - A 档：主方案 skill ≥ 0.3、R² ≥ 0.5（分类 AUC ≥ 0.75），且所有验证方案都优于基线。
  - B 档：优于基线，但未达 A 档。
  - C 档：不优于基线。
- **主方案成绩是开发集交叉验证成绩**。最优模型类别是按同一份外层成绩选出来的，所以成绩略偏乐观。M3 的外部检验没有这项偏差。
- **外部检验**用 12 条选择轨迹。每个任务的最终模型在上面只评一次。调参、阈值选择、学习曲线都不使用这 12 条轨迹。
- **分类阈值**从不在被评估的同一批预测上选。
  - M3 的阈值只用开发集折外预测确定，然后在外部集上评估。
  - M4 没有外部集，用交叉拟合：每一折的阈值只用其余几折确定。
- **学习曲线**只在开发集内部做：按轨迹 5 折，每折从训练轨迹中抽样训练。模型类别和超参数与最终模型一致。

### M3 外部检验

用 27 条开发轨迹训练，在 12 条从没见过的中间档轨迹上测（车速 2.5/3.5 m/s、转向速率 3/6°/s）：

| 目标 | skill | R² / AUC |
|---|---:|---:|
| RIGHT 不足率 | 0.71 | R² 0.87 |
| 近场点误报率 | 0.76 | R² 0.90 |
| RIGHT 不足率 − 无后处理 | 0.79 | R² 0.93 |
| 近场点误报率 − 无后处理 | 0.84 | R² 0.95 |
| 出现窗口漏报 | 0.83 | AUC 0.994 |
| 误报预算达标 | 0.80 | AUC 0.994 |

混淆矩阵见 `M3_二级处理联合/figures/fig06`：
- "出现窗口漏报"：外部集里 458 行漏报全部识别出来，0 行漏判，另有 112 行误判。
- "接触前完全无报警"：用安全优先阈值，399 行里漏判 5 行。

### M4 交叉拟合阈值

安全优先阈值的目标召回是 90%，三个分类任务实际召回为 0.88、0.89、0.90，略低于目标。这正是阈值不在同一批预测上选择时的正常现象。

### 学习曲线（开发集内部）

每折训练轨迹从 5 条增加到 15 条时，误差明显下降。从 15 条到全部（约 21 条）时，曲线基本变平。以 skill 为例：

- RIGHT 不足率：0.64 → 0.75 → 0.78
- 近场点误报率：0.80 → 0.89 → 0.91

结论：在 10° 这一种几何内，现有同类轨迹数量已接近饱和。要扩大适用范围，需要新的转弯几何，而不是更多同类轨迹。

### 主要规律

1. 后处理三个因素（窗口 W、膨胀、确认）是最重要的特征组。确认时间对误报影响最大，其次是噪声。
2. 确认 0.1 s：近场误报下降约 8–9 pp，但窗口漏报率上升约 0.6 pp，RIGHT 不足率上升约 2.4–2.7 pp。膨胀 0.05 m 时没有窗口漏报。
3. 扩窗到 W=3 s：不加确认时迟报几乎不变（≤0.01 pp），近场误报增加约 2–6 pp。
4. 趋势增益越大，迟报越低、误报越高（`描述性图表/fig07`）。
5. 状态估计（φ EKF、α 低通）能降低误报，但会带来窗口漏报。raw 输入下有窗口漏报的行数是 0，加 α 低通后是 51。

## 要注意的地方

- 窗口漏报分类的 AUC 达到 0.99，主要是因为漏报几乎由设计参数决定：确认 0.1 s 且膨胀小于 0.05 m 时才会出现。模型基本是学到了这条规则，不代表它能预测更复杂的情况。
- 目标点、帧和噪声种子都不是独立的车辆试验。所有验证都按整条轨迹分组。
- M4 的增益细档只来自 12 条选择轨迹，而这 12 条在原计划中属于调参数据。
- 不能声称以下任何一项：
  - 覆盖了真实城市路口
  - 零漏报验收通过
  - 找到了部署最优参数
  - ESP32 实时性达标
  - 结论已在修正标签下复核
  - 分档等同于科研准入
