半挂车右转盲区预警项目工作总结流程图

按“问题发现 → 工具建设 → 算法统一 → 当前成果”的因果顺序整理
一句话总结：本项目已经从“能预测半挂车右转扫掠区”推进到“能用统一 CFG 策略和 segment_swept 裁判，系统评估右转全过程中报警提前量不足的盲区点分布”。
一、主模型建立

项目目标确定

面向半挂车右转内轮差风险，识别行人/非机动车进入挂车右侧扫掠危险区的情况。

right-turn blind zone

建模定位

将项目定义为短时风险预测问题，而不是车辆控制或长期驾驶意图识别问题。

short-horizon prediction

半挂车运动学

基于实时 v、alpha、phi 推演 B/H/T 等关键点，保留 l_h * omega1 耦合项。

kinematics_step

三层预测区

构造 PolyW / PolyA / PolyI，对应预警、报警、立即危险三个时间尺度。

PolyW / PolyA / PolyI
二、问题发现

PID 工况导出

用 PID 工况仿真导出器生成可控 CSV，作为没有实车时的虚拟传感器输入。

v(t), alpha(t), phi(t)

Phase 1 验证链

CSV 回放、MATLAB 重算、扫掠区预测、真值轨迹对比，形成早期闭环验证。

CSV replay

R3 晚报暴露

R3 位于出弯边缘，首次 Poly 报警偏晚，提示出弯阶段预测窗口可能不足。

R3 late warning

TTC 复盘定位

TTC 用于后验真实接触和提前量复盘，不替代在线 Poly 预测判警。

true-TTC replay
三、工具链扩展

出弯状态机

针对正交路口，使用累计航向角、alpha 回正、phi 滞后判断 ENTRY / MID / EXIT。

EXIT phase

全过程盲区分析

将问题从 R3 出弯扩展到入弯、弯中、出弯全过程的时间盲区分析。

lead_W < threshold

边界点与日志

沿真实扫掠边界生成目标点，记录 first_PolyW、true_contact_time、lead_W 和事件类型。

boundary targets

阈值扫描

用 MATLAB 扫描 0.1 到 3.0 秒反应时间阈值，生成盲区点分布与叠加图。

threshold scan
四、算法统一

CFG 策略系统

用 JSON 统一状态机阈值与 default / EXIT 阶段预测窗口，支持导入、导出和配置生成器。

strategy CFG

扩窗非单调问题

发现长窗口大 Poly 可能自交退化，导致 3s 扩窗反而漏掉 2s 已覆盖点。

large Poly issue

segment_swept 裁判

改为按相邻预测步右沿形成的小四边形逐段判内，保证扩窗只增加后续扫掠段。

segment_swept

统一与标记

网页、MATLAB 校验、阈值扫描、正交路口 demo 统计命中统一；TTC 保持后验复盘定位。

single judging logic

关键因果链 1

R3 出弯晚报 → 讨论出弯识别 → 引入正交路口状态机 → 形成 EXIT 扩窗策略。

关键因果链 2

全过程存在反应不足点 → 建立盲区分析软件 → 生成边界点 → 阈值扫描分布规律。

关键因果链 3

扩窗结果不稳定 → 发现大 Poly 自交问题 → 改用 segment_swept → 统一裁判口径。

当前边界：TTC 软件不参与 CFG 扩窗裁判；MATLAB 正交路口图暂时仍画 Poly 形状参考；权威统计结果以 segment_swept 日志和阈值扫描为准。
