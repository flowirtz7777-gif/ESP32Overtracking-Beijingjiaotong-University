## 1. 项目目前做到哪里

当前最准确的定位是：**已经形成围绕半挂车右转风险的仿真研究工具链；完整多传感融合实车预警系统尚未完成。**

软件侧可以生成工况、读取车辆状态、进行短时运动学预测、比较转向预测假设、复盘报警提前量、分析出弯阶段并统计预警不足。硬件侧目前仍是接入骨架，不能把方案文档中的全部模块视为已经实现。

| 模块 | 已有成果 | 当前边界 |
|---|---|---|
| 工况生成 | PID生成器；人工驾驶仿真器的WASD、CSV导出、阶段日志和Replay代码 | 都是虚拟运动学工况，不是真实道路驾驶数据；人工驾驶新工具本机已做静态检查，本次未重新做交互验收 |
| 耦合运动学 | MATLAB状态递推、关键点推导，保留后轴至牵引销偏置耦合项 | 最新复算仍未通过项目设定的1毫米位置门槛；不是已通过的MATLAB/C++对齐验收 |
| 短时危险区 | 0.3/1/2秒分层预测；当前车身占用区BodyNow兜底 | 主要针对挂车H-T右侧边缘；不等于整车所有边缘及车头危险均已覆盖 |
| 转向预测比较 | 保持、线性外推、二阶外推、多假设并集、扇形包络五种实现和比较工具 | 已有单工况结果，不足以证明任一方案在所有工况下最优 |
| 出弯策略 | IDLE/ENTRY/MID/EXIT/DONE状态机；EXIT阶段扩窗；JSON配置接入 | 当前阈值主要面向正交约90度转弯；不是已经泛化的任意路口识别器 |

| 固件与融合 | ESP32目录、传感器接入文件、系统和接口设计文档 | `alarm_out.h`缺失，CAN解码、雷达完整解析、预测器、风险评估、视觉通信和融合未补齐；未达到固件可编译验收 |
| 项目材料 | 核心设计、算法说明、使用资料、申报和答辩资料及历史结果已分类归档 | 材料齐全不代表材料中的技术指标都已被实验验证 |

## 3. 工具链应该怎样串起来

```text
PID工况 / 人工驾驶仿真
        -> 工况CSV
        -> 一阶保持复算，检查积分、单位和时间对齐
        -> 五种alpha方案比较 / 正交出弯策略
        -> 全过程盲区分析，固定目标和评价参数
        -> MATLAB交叉核验与阈值扫描
        -> 留存CSV、CFG、目标集、图、日志和实验结论

工况完整未来轨迹 -> 后验接触时刻/TTC -> 评价预测是否足够提前
当前帧车辆状态   -> 在线预测危险区   -> 首次预测命中
```

完整未来轨迹只能用于离线评价和构造测试靶标，不能作为在线预测输入。TTC复盘软件使用后验true TTC，因此不能把复盘画面中的提前变色直接当作在线预警成功。

### 第一步：先复现已有基准工况

建议从现有 `pid_scenario_20260530_020804.csv` 开始，再添加自己的新工况。MATLAB中执行：

```matlab
cd('E:/大创内轮差项目/工具/alpha一阶保持仿真');
clear functions
out = run_phase1_demo( ...
    'scenarios/pid_scenario_20260530_020804.csv', ...
    '../验收目标集/出弯测试.csv');
```

检查 `out.run_dir` 中的summary和图，尤其是位置误差及门控状态。多个工具存在同名函数，不建议一次性用genpath把全部工具加入路径；切换实验目录时可先清理已加载函数缓存，再确认调用入口。

### 第二步：比较转向预测假设

```matlab
cd('E:/大创内轮差项目/工具/alpha方案对比');
clear functions
out = compare_alpha_schemes('pid_scenario_20260530_020804.csv');
```

该入口读取相邻 `alpha一阶保持仿真/scenarios` 中的同名CSV。新工况用于该工具时，需要先放入上述目录。比较工具内部生成并固定一组目标供五方案共同使用，但这组点不自动等同于验收目标集中的R1-R5/R3；不能仅凭同名R3跨工具合并结论。

比较图能回答“哪种方案更保守、在这些点上提前多少”，不能单独回答“实际误报率是多少”。当前面积统计抽取20个关键帧，预测命中扫描约每0.16秒一次；细微差异需按更密集、统一的时序口径重新评估。

### 第三步：使用人工驾驶软件扩充工况

双击本工具BAT，保留默认参数，开始驾驶后用W/S加速或制动、A/D转向；结束后导出工况与阶段日志，再用Replay检查轨迹。先增加“较早回正、较晚回正、减速出弯、转向变化较快”等有明确差异的样本。

它扩充的是人工操作的模拟工况，不是真车采样。接入MATLAB前要核验输入记录与状态更新时间：记录在步末的控制量和用于推进下一步的控制量不是同一语义，CSV列名兼容不等于数值递推已经等价。同事README中的接入测试是已有记录，本指南不把它当作本次重新复现的实验。

### 第四步：公平比较普通窗口与EXIT扩窗

现有可用配置在 `工具/转弯全过程盲区分析软件/CFG配置`：

- `default_cfg.json`：普通窗口策略。
- `exit_window_test_cfg.json`：普通阶段W/A/I为2/1/0.3秒，EXIT为3/1.5/0.5秒。

部分旧说明提到 `default_exit_window_cfg.json`，当前实际文件名以上述两个为准。

打开全过程盲区分析软件，导入同一场景CSV和同一固定目标CSV，设置一致的反应阈值、判内容差和起始截断参数。先导入普通配置刷新并导出日志，再导入EXIT配置刷新并导出日志。不要比较时重新随机生成目标；也不要在换工况后继续使用旧工况的接触时间元数据。

初次可以使用配套的 `验收目标集/出弯测试.csv` 做小规模检查；正式统计应使用同一工况生成、冻结并复用的较密集边界点集，同时另设不会接触车辆的负样本。

主要看以下量：

- `lead_W = true_contact_time_s - first_PolyW_s`：黄色层首次预测命中的提前量。
- `BLINDSPOT_REACTION_INSUFFICIENT`：提前量低于本次设定的反应阈值。
- `POLYW_NO_HIT`：未预测命中，须单独计数，不能忽略。
- `STARTUP_TRUNCATED`：起始历史不足的点，单独报告。
- 状态、CFG名、窗口、预测步长和命中方法：用于核查比较口径是否一致。

默认反应阈值1秒是分析设置；0.3/1/2秒是当前分级预测参数，均不是已经实验确定的普适最优值或安全保证。

### 第五步：MATLAB核验网页结果

```matlab
cd('E:/大创内轮差项目/工具/转弯全过程盲区分析软件');
clear functions
scenario = '../alpha一阶保持仿真/scenarios/pid_scenario_20260530_020804.csv';
targets = '../验收目标集/出弯测试.csv';
report = validate_turn_exit_targets( ...
    scenario, targets, '', 0.05, 2.0, 'CFG配置/default_cfg.json');
```

第三参数为空时只运行MATLAB评价；提供真实导出的网页日志CSV路径才会进行网页对照。比较EXIT时将最后一项换成 `CFG配置/exit_window_test_cfg.json`，其余参数保持不变。网页日志也必须来自同一配置和同一组输入。

阈值扫描入口为：

```matlab
opts = struct('strategy_cfg_json', 'CFG配置/default_cfg.json');
scan = scan_ttc_threshold_blindspots(scenario, opts);
```

扫描用于看评价结论对反应阈值的敏感性。默认扫描会生成场景边界点，跨配置比较仍应核对目标坐标和接触时间是否完全一致。图和日志写入本工具logs下的独立运行目录。

正交状态机的单独演示入口：

```matlab
cd('E:/大创内轮差项目/工具/正交路口出弯状态机仿真');
clear functions
out = run_phase1_demo( ...
    'scenarios/pid_scenario_20260530_020804.csv', ...
    '../验收目标集/出弯测试.csv', ...
    '../转弯全过程盲区分析软件/CFG配置/exit_window_test_cfg.json');
```

全过程统计采用 `segment_swept`，即逐段小扫掠四边形判内。旧alpha demo和比较工具仍有大Poly的处理口径；正交MATLAB图也保留大Poly可视化参考。因此正式研究不能混用不同工具的图、判内方法和提前量数字。CFG链目前只执行hold；安全膨胀字段虽存在，但未实际启用几何膨胀。

## 4. 已有运行结果能说明什么

### 4.1 最新运动学复算

证据：`工具/alpha一阶保持仿真/runs/20261010_163006__pid_scenario_20260530_020804/summary.txt`。

- 1751个采样，步长0.02秒，总时长35秒，平均速度3米/秒。
- xB最大绝对差0.004114米，yB为0.004628米，即约4.1和4.6毫米。
- 航向和铰接角误差很小；但位置未通过项目自定的1毫米门槛。

这证明入口可运行并产出复算结果，不证明门控已通过。误差来源还需核验积分方法、时间对齐和生成器处理，不能未经定位就断言已经解决；该门槛也不是实车精度认证。

### 4.2 五种转向方案的单工况对比

证据：`工具/alpha方案对比/runs/20260929_195655__pid_scenario_20260530_020804/summary.txt`。

| 方案 | 平均PolyW面积（平方米） |
|---|---:|
| 保持 | 4.556 |
| 线性外推 | 4.506 |
| 多假设并集 | 6.879 |
| 扇形包络 | 39.057 |
| 二阶外推 | 4.572 |

扇形包络面积约为保持的8.6倍，部分目标的PolyA提前量更大；该次R6只有扇形预测命中，但提前量仅0.16秒。这是“更大包络可能增加覆盖，却不自动等于足够反应时间”的具体例子。

在该单工况下，线性和二阶外推没有呈现对所有测试点的明显优势。不要从此推出“外推永远无效”；也不能从包络面积大推导实测误报率高，更不能宣称其在所有真实轨迹上绝不漏报。

### 4.3 历史阈值扫描

证据：`工具/转弯全过程盲区分析软件/logs/threshold_scan_20260601_011942/threshold_scan_counts.csv`。

该次历史扫描的反应阈值为1、2、3秒时，计数分别为70、843、1938。它说明评价对阈值敏感，不是当前EXIT策略相对基线的成效证明；这些是被采样点的计数，不是事故概率、实车漏报率或独立交通场景数量。

## 5. 是否具有科研意义

**有研究意义，但研究贡献需要从明确问题、对照实验和适用边界中建立，不能仅由工具数量或系统名称推出。**

### 应用问题是成立的

大型车辆侧方自行车碰撞预警是已有的道路安全议题。联合国UN R151专门讨论自行车盲区信息系统，文本也区分驾驶员反应时间与包含反应、减速过程的停车距离。这支持研究预警时效的现实价值，但本项目没有据此完成法规符合性认证。

来源：[UNECE UN R151页面](https://unece.org/transport/documents/2021/08/standards/un-regulation-no-151-blind-spot-information-system-detection)、[官方文本](https://unece.org/sites/default/files/2021-08/R151e.pdf)。

### 基础运动学和扫掠区不是天然的新颖点

既有研究已经用牵引车-挂车模型和车身扫掠区域讨论道路规划与避障。例如Oliveira等人的原始论文研究了铰接车辆扫掠区域和off-track问题。因此，不能把“使用运动学”“画出扫掠区”本身表述为首次创新。本次文献核查不是系统性综述，尚不能认证任何候选方法的新颖性。

来源：[Optimization-Based On-Road Path Planning for Articulated Vehicles](https://arxiv.org/abs/2001.06827)。

### 最值得聚焦的三个候选贡献

1. **出弯阶段的预警不足机制。** 分析转向回正与挂车姿态滞后为何使保持模型在特定位置报警偏晚，明确发生的参数和工况条件，而不是只展示一个R3反例。
2. **因果分阶段窗口策略。** 只利用当前及历史状态识别EXIT，在该阶段扩窗；检验是否比固定窗口更早，又比全过程统一大窗口更少保守覆盖。
3. **预警有效性的时空评价。** 将“有没有命中”细分为“提前量是否足够、哪些位置不足、不同阈值下结论如何变化”，形成可复现评价流程。

`segment_swept`具有修正长窗口大多边形自交和非单调判内的工程价值。同一初态、输入假设、步长和容差下，增加预测段有助于保持集合包含关系；这不是对真实驾驶变化和系统安全性的全面保证，其独立学术新颖性也仍需文献检索。

## 6. 接下来怎样补齐科研证据

| 优先级 | 要完成的实验 | 为什么重要 |
|---|---|---|
| 1 | 统一CSV控制量时间语义、积分方式、判内方法和采样步长，定位当前毫米级差异 | 先排除实现或评价口径造成的假差异 |
| 2 | 多工况三组核心对照：固定2/1/0.3秒、全过程固定3/1.5/0.5秒、仅EXIT扩窗 | 分离“窗口变大”的收益与“分阶段”的独立收益 |
| 3 | 改变车速、车辆尺寸、回正时刻和转向变化；设置未用于调阈值的测试工况 | 防止只对一个工况或一个目标点调参 |
| 4 | 加入不接触的负样本、动态目标和目标尺寸 | 才能评价误报/漏报，而不只是危险区面积 |
| 5 | 加入状态噪声、延迟和更新率变化；测量真实运行耗时 | 检查鲁棒性及实时性，区分预算与实测 |
| 6 | 对接台架或独立实测轨迹，再做低速场地测试 | 同模型仿真主要验证自洽，不是独立物理准确性验证 |
| 7 | 补齐传感器解码、标定、关联、融合和报警固件 | 才能支撑“多传感融合实时预警系统已完成”的说法 |

建议报告有效危险目标上的提前量分布、反应不足率、未命中率、各阶段结果；在明确的负样本上报告误报率，同时报告保守覆盖面积和计算耗时。所有比例要写清分母，边界点不应当作独立交通场景；跨多个工况汇总时应以工况为统计单位并报告差异范围。

如果加入静态危险带、忽略挂车姿态的单车体模型等对照，会更有利于说明耦合预测的价值。它们当前属于设计思路，不应列为已经完成的可运行比较。PID负责生成可重复工况，不是与主预警器公平竞争的另一种预警算法。

## 7. 对外表述建议

可以说：

> 已完成半挂车右转短时风险预测的仿真工具链，实现了耦合运动学、分层扫掠预测、转向假设对照、出弯阶段策略和报警提前量评价；目前正在统一数值口径、补充多工况与独立验证，并推进传感器融合和硬件实现。

目前不宜说：已完成实车多传感融合、证明最优预测窗口、保证无漏报、实测50Hz/2毫秒、验证事故降低比例或已符合相关法规。

总体判断：作为大创的中期仿真与方法研究基础，已有较扎实的工作积累；作为完整系统交付或已被充分验证的学术结论，仍需上述实验和硬件证据。
