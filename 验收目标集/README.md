# 验收目标集（冻结）

这里存放**冻结的固定目标集** CSV，供 TTC 复盘软件和 MATLAB 诊断脚本共用。

> ⚠️ **为什么要冻结**：v1.0.2 第一轮做 alpha 方案对比时，对比脚本让各方案
> 各自沿挂车右沿现生成目标点（`local_make_fixed_targets`），结果 summary 里
> R3 的接触时刻（17.92s）和复盘文档固化的 R3（16.24–18.12s）对不上，
> 导致"R3 是否被解决"的结论无法横向比较。教训：**验收目标集必须固定、
> 跨方案不变、跨工具一致**。本目录就是这个唯一事实来源。

## CSV 格式约定（TTC 复盘软件可直接上传）

- 表头需含列对之一：`x,y` 或 `x_m,y_m` 或 `target_x_m,target_y_m`
- 多出的 `name` 列会被工具忽略（仅供人读）
- 坐标为世界系米制，与场景 CSV 同一坐标系

上传方式：TTC 复盘软件 →「1. 场景与目标」→「导入目标 CSV」→ 选本目录文件。
记得「导入场景 CSV」选 `pid_scenario_20260530_020804.csv`。

## 归因结论摘要（截至本轮，hold 基线）

`R3诊断/diagnose_R3_hold.m` 三路对比（真值扫掠 / 全区域并集 / 仅最大区域）显示：

- PolyA 层 R3 落入"被丢弃非最大区域"的决策帧数 = **0**
- → polyshape「取最大连通区域」**不是** R3 晚报的原因（猜测被证伪）
- → 连真值扫掠 swept_truth 自身也要到 15.80s 才纳入 R3，瓶颈在 **horizon 内
  的 φ 姿态演化（出弯滞后）**，不在多边形后处理

下一步（出弯相位识别 + 受限回正预测）尚未动手，**本轮不改 alpha 模型**。
